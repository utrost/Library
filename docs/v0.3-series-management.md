# Series management in 0.3

The **Series** page shows account-private series identities imported from EPUB/OPF and later metadata edits. A book currently has one linked series and one part label. Its imported `series_name` and `series_number` remain the source values; the linked identity is the preferred catalogue grouping. Editing a series name changes only the preferred display name.

## Move and merge

Open a series and expand **Move or merge books**. Select one or more books to move just those books. Leave every checkbox clear to merge the entire source series. Search for a destination series or create one, then review the book list and confirm. One operation is limited to 500 books and 8 MiB of journal data. For a larger series, move selected books in batches, then merge the empty source identity to redirect future imports. A durable background merge remains future work.

A whole-series merge moves its current books and retires its source identity. Future imports using the old source name resolve to the destination. A selected-book move leaves both identities active. Both actions preserve the original book metadata and source files. **Recent changes** records a private, bounded summary and offers conditional Undo. Undo succeeds only while the affected books, assignments and source identity still match the applied operation. It will refuse to overwrite later edits or imported changes.

## Changed imported metadata

A manual assignment survives an unchanged rescan. If a later import changes its series name or part number, the linked series remains in place and the book enters **Review imported series changes**. **Keep assignment** accepts the new source checkpoint while retaining the chosen identity; **Use imported series** follows the imported name, including any merge redirect. Both choices reject stale review tokens. The review is private to the book owner.

The source series/part values are still used in metadata editing, exports and scanner precedence. This separation prevents a catalogue organization choice from silently rewriting an EPUB or OPF sidecar. A series identity is account-scoped; merging cannot cross accounts.

## Storage and migration

`Version000300Date20261014120000` adds `library_series.merged_into`, `library_item_series.assignment_source`, and the `library_series_operations` journal. Existing links default to `import`, so installed libraries retain their current behavior. `series_sync_status=3` means a protected manual assignment has changed imported source data and needs review. The indexed pending queue remains for ordinary projection work; conflict rows are not retried automatically.

The operation stores a before/after snapshot and a review fingerprint. Preview and apply use the same owner-scoped book set, reject changed assignments, and acquire item/account locks before writing. Account deletion removes the journal. The persistent source metadata is never mutated by a move, merge or Undo.

## Current limits

- The first release supports one series slot per book. Multiple series memberships and natural ordering of labels such as “Book One” are separate work.
- Interactive whole-series merges stop at 500 books. Selected-book moves can be repeated for larger catalogues; the empty source identity can then be merged to establish the redirect.
- The journal retains recent operations without automatic expiry; Undo is conditional on the current state and can become unavailable after later work.
- The focused test script `scripts/smoke-series-assignment.mjs` uses a disposable two-EPUB account and records Chromium/Firefox screenshots. `tests/php/series_assignment_integration.php` exercises redirect, rescan preservation, stale changes, review and Undo.

# Language normalization and review

Library stores one or more language codes in the book's existing `language` field. The Full details picker remains the per-book editor. New scans normalize clear source values, for example `EN` → `en`, `en-us` → `en-US`, `eng` → `en`, and `English` → `en`. Mixed case is accepted. Distinct codes retain their order; repeated codes are removed. The exact source value is retained in `field_values.languageOriginal` for new scans.

Values that cannot be safely interpreted, such as `3ng` or `en-en`, stay as source text and appear under **Review languages**. A user can map that repeated source value to one or more codes for all matching books or ignore it. Decisions belong to the current account and do not modify EPUB, PDF, OPF or Nextcloud Files. A manually corrected language field, including a legacy whole-book edit, is never overwritten by a mapping or automatic backfill.

The review page advances bounded discovery of existing books and application of approved mappings; Nextcloud background jobs continue the same work. A mapped language is marked as a protected field so later scans cannot silently restore the malformed source value. Ignored values stay out of the queue after rescan. New or changed source language values are reconsidered. Automatic backfill normalizes confidently recognizable older values only when the language field is not protected.

`Version000300Date20261018030000` adds two account-owned tables, `library_language_candidates` and `library_language_mappings`, plus a nullable `library_items.language_review_hash` cursor. The imported source text remains in the existing provenance map. No language identity table is added because the code vocabulary is standardized. The existing catalogue language predicate still matches complete semicolon-separated tokens; its large-library cost remains to be measured.

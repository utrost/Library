# Pre-release architecture plan

This plan follows the [2026-10-15 review](pre-release-architecture-review.md). The changes are in the working tree, not in a deployed release. Focused disposable acceptance and [signed fresh-install and upgrade matrices](compatibility-evidence/2026-10-15-signed-architecture-candidate/README.md) have run; populated-library and human acceptance remain.

**Measured this slice:** 9/9 fresh schema checks passed on NC33.0.9, 34.0.4 and 35.0.0 with SQLite, MariaDB and PostgreSQL. Alpha.9-to-candidate upgrade passed on NC34 with all three engines. A full disposable NC34 backup/restore preserved books, corrected metadata, author merge and portrait, series merge, and list note. The 100,000-change journal benchmark drained in 251 pages and 1.8 seconds with about 2 MiB additional peak memory; a concurrent generation survived. Synthetic root deletion of 100,000 file/book rows took 2.9 seconds on SQLite and 6.5 seconds on MariaDB. The signed package build passed 1,045 Python tests, PHP runtime checks, dependency audit, signature, archive, SBOM and provenance checks. Its exact archive passed 35/35 Playwright checks and additional feature smokes on each of NC33, NC34 and NC35 with the 40 Gutenberg books, both fresh and upgrading from 0.2 beta. These are source-tree/disposable checks, not a real 100,000-file scan or owner acceptance.

## Immediate acceptance for findings 1–3

1. On two separate Nextcloud accounts, try a valid ISBN edit against the other account's book ID. The disposable service check rejected the edit and left identifiers and details private. Browser 404, search, full-details and catalogue drawer checks remain.
2. Open one book in two tabs; save a metadata change in the first, then try to save the stale draft in the second. The disposable service check rejected the stale edit. The native form now returns a 409 comparison page with both values, retains its draft and supports explicit reviewed resubmission; its NC34 browser smoke passed. JavaScript editor draft preservation and consecutive autosaves still need exact-package acceptance.
3. Cause an index write failure inside a metadata edit and confirm the item, identifiers, facets, search grams and duplicate index all roll back. Injected facet-write failures passed for full and batch edits on disposable NC34; broader derived-index inspection remains.
4. Delete a missing book and a root containing indexed books, including edited books and reading-list entries. A disposable NC34 check confirmed child-row removal and the unavailable list placeholder with its note. Missing-book, duplicate-review and interrupted-transaction cases remain.
5. Observe bounded orphan repair on an upgraded copy of the populated NC34 database. Check root deletion during indexing and extraction, and populated scan throughput. Synthetic 100,000-item root deletion took 2.9 seconds on SQLite and 6.5 seconds on MariaDB without derived-row fanout; a populated rehearsal is still needed. If contention or transaction size is unacceptable, use a resumable deletion state before release.

## Release order

Close the remaining populated-instance and targeted browser acceptance above. Then build the final versioned release archive from a committed tree and repeat the signed integrity and smoke gate as needed. The signed alpha.9 candidate already passed fresh-install and 0.2-beta-upgrade browser checks on Nextcloud 33, 34 and 35 with the 40 English Gutenberg books; its evidence is linked above. Owner human acceptance follows the [test handbook](human-test-handbook.md). E can continue after the first release as contained refactors.
